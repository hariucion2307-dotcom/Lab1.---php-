Задание 1. Анализ HTTP-запросов. Часть 1
•  URL запроса:
[https://en.wikipedia.org/wiki/HTTP](https://en.wikipedia.org/wiki/HTTP) -полный адрес запрашиваемого ресурса в сети интернет, включающий протокол (https), доменное имя (en.wikipedia.org) и путь к конкретной статье (/wiki/HTTP).
•  Метод запроса и причина его использования:
Используется метод GET. Данный метод применяется потому, что задача клиента заключается исключительно в получении (запросе) существующего документа с сервера без попытки его изменения, удаления или создания новых данных. Метод GET является безопасным и идемпотентным (многократный повтор запроса не меняет состояние сервера).
•  Статус ответа и его значение:
Получен статус ответа 200 OK. Это стандартный код успешного HTTP-ответа, означающий, что сервер успешно обработал запрос клиента и передал запрашиваемый документ в теле ответа.
•  Заголовки запроса и ответа:
•	Заголовки запроса (Request Headers): Содержат метаданные, отправляемые браузером. Например, Host указывает целевой сервер, User-Agent сообщает информацию об операционной системе и версии браузера клиента, а Accept описывает типы медиаданных, которые клиент готов принять (например, text/html).
•	Заголовки ответа (Response Headers): Содержат информацию, возвращаемую сервером. Например, Content-Type указывает формат передаваемых данных (например, text/html; charset=UTF-8), Content-Encoding показывает тип примененного сжатия (gzip), а Server информирует о программном обеспечении веб-сервера.
•  Наличие тела запроса или ответа:
•	У отправленного GET-запроса тело (Request Body) отсутствует, так как все необходимые параметры передаются непосредственно в строке URL или через заголовки.
•	Тело ответа (Response Body) присутствует и содержит полный исходный HTML-код страницы Wikipedia (включая разметку документа, текст статьи и ссылки на сопутствующие ресурсы).
•  Дополнительные запросы при загрузке страницы и причины их отправки:
При открытии страницы помимо основного HTML-документа браузер автоматически отправляет десятки дополнительных запросов. Это необходимо для подгрузки связанных ресурсов, указанных в коде страницы: таблиц стилей (.css), скриптов JavaScript (.js), изображений (.png,  .svg), иконок (.ico) и шрифтов. Без них корректный визуальный показ и интерактивность сайта невозможны.

Задание 2. Анализ HTTP-запросов. Часть 2
•  URL запроса и параметры поиска:
При выполнении поиска по слову browser на странице [https://en.wikipedia.org/wiki/Special:Search](https://en.wikipedia.org/wiki/Special:Search) в панели Network формируется запрос со следующим URL:
[https://en.wikipedia.org/w/index.php?search=browser&title=Special%3ASearch&profile=advanced&fulltext=1&ns0=1](https://en.wikipedia.org/w/index.php?search=browser&title=Special%3ASearch&profile=advanced&fulltext=1&ns0=1)
•  Метод запроса и причина его использования:
Используется метод GET. Он применяется потому, что поисковый запрос запрашивает у сервера результаты фильтрации данных и не вносит изменений в базу данных сайта (операция является безопасной и идемпотентной).
•  Query Parameters (Параметры строки запроса):
•	Search=browser - основной параметр запроса, содержащий поисковый запрос пользователя (слово, которое мы искали).
•	title=Special:Search - служебный параметр, указывающий внутренний системный путь страницы поиска Википедии.
•	profile=advanced - задает расширенный профиль или режим поиска.
•	fulltext=1 - указывает серверу выполнять полнотекстовый поиск по содержимому статей.
•	ns0=1 - определяет область поиска (пространство имен с индексом 0, то есть основные статьи энциклопедии).

Задание 4. Составление HTTP-запросов
1. GET-запрос к серверу с указанием User-Agent
Запрос:
GET / HTTP/1.1
Host: sandbox.usm.com
User-Agent: Ion Hariuc 

Что такое User-Agent и для чего он используется?
User-Agent - это стандартный заголовок HTTP-запроса, содержащий строку с информацией о клиенте (браузере, операционной системе, версии приложения и устройстве), который отправляется серверу.
Используется для того, чтобы сервер мог адаптировать выдаваемую страницу под конкретное устройство пользователя (например, десктоп или мобильный телефон), собирать аналитику о посетителях, а также для корректной фильтрации ботов и поисковых роботов.
2.POST-запрос к [http://sandbox.usm.com/cars](http://sandbox.usm.com/cars)
Запрос:
POST /cars HTTP/1.1
Host: sandbox.usm.com
Content-Type: application/x-www-form-urlencoded
Content-Length: 31

make=Toyota&model=Corolla&year=2020
•	Какие еще методы HTTP-запросов существуют и для чего они используются?
o	HEAD - аналогичен методу GET, но сервер возвращает только заголовки без тела ответа (применяется для проверки доступности ресурса или получения его метаданных).
o	DELETE - используется для удаления указанного ресурса на сервере.
o	OPTIONS - запрашивает список параметров соединения или разрешенных методов для конкретного ресурса (часто используется при проверке CORS-политик).
o	TRACE - выполняет эхо-тестирование по пути следования запроса (применяется для отладки).
o	CONNECT - преобразует соединение в прозрачный TCP/IP-туннель (используется, например, для работы через прокси с поддержкой SSL/TLS).
3. PUT-запрос к [http://sandbox.usm.com/cars/1](http://sandbox.usm.com/cars/1)
Запрос:
PUT /cars/1 HTTP/1.1
Host: sandbox.usm.com
User-Agent: Ion Hariuc 
Content-Type: application/json
Content-Length: 46

{
  "make": "Toyota",
  "model": "Corolla",
  "year": 2021
}
В чем разница между PATCH и PUT запросами?
•	PUT подразумевает передачу полного представления ресурса. Если ресурс существует, он полностью перезаписывается новыми данными; если нет - создается заново.
•	PATCH используется для частичного обновления ресурса. В теле передаются только те поля, которые нужно изменить, а остальные свойства объекта остаются неизменными.
4. Ответ сервера на отправленный POST-запрос
HTTP/1.1 201 Created
Content-Type: application/json

5. Ситуации возникновения HTTP-кодов состояния
•	200 OK - Запрос выполнен успешно, сервер вернул запрошенные данные (например, список автомобилей).
•	201 Created - Запрос успешно выполнен, и в результате был создан новый ресурс (например, успешно добавлена новая машина через POST-запрос).
•	400 Bad Request - Сервер не смог обработать запрос из-за синтаксической ошибки или неверно переданных параметров со стороны клиента.
•	401 Unauthorized - Пользователь не прошел аутентификацию (отсутствуют или недействительны данные для входа).
•	403 Forbidden - Сервер понял запрос, но отказывается его выполнять из-за ограничения прав доступа пользователя.
•	404 Not Found - Запрашиваемый ресурс (страница или путь) не найден на сервере.
•	500 Internal Server Error - Внутренняя непредвиденная ошибка на стороне сервера при попытке выполнить запрос.
